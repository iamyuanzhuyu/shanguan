# 山观 · 徒步登山天气与景观预测

一个无构建、无框架的静态网页应用：本地山峰库 + 高德 POI 搜索目的地，Mapbox GL JS 渲染地图，
Open-Meteo 提供多模型天气预报，并计算云海概率与日出观赏条件。

## 运行方式

直接双击 `index.html` 即可（高德接口走 JSONP，`file://` 下可用）。
如需本地静态服务：

```powershell
npx http-server -p 8080
```

## 搜索数据源（省高德配额）

| 顺序 | 数据源 | 说明 |
|---|---|---|
| 1 | 本地山峰库 `peaks-db.js` | 零请求；热门徒步、常见景区、广东热门共 133 条，精确/前缀命中时**完全不打高德** |
| 2 | 高德 Web 服务 | `inputtips`（下拉建议）/ `place/text`（精确搜索、行政区解析）/ `regeo`（逆地理），返回 GCJ-02 后转 WGS-84 |
| 3 | Mapbox Geocoding v6 | 兜底：高德 key 失效、超限、超时或查不到时使用，返回 WGS-84；结果标注「Mapbox 兜底」，可能只是行政区近似点 |
| 4 | 经纬度 | 直接输入 `27.47,114.17` 选点 |

高德候选的几个细节：

- `inputtips` 对**乡镇/行政区**（如"大布镇"）只给名称、行政区，不给坐标。这类候选会照常出现在下拉里
  （标注「点击后定位」），选中时再用 `place/text` + `adcode` 精确解析坐标，避免直接丢掉；
- 同名地点不合并：「大布镇」山东聊城、广东乳源是两条候选，都保留；
- 高德 JSONP 失败（网络抖动/瞬时超限）自动重试一次；**空结果不写缓存**，不会把一次失败记住 5 分钟。

### 手动输入经纬度

搜索（本地库 → 高德 → Mapbox）全部没有命中时，会自动弹出「手动输入经纬度」对话框；
也可以随时点搜索框右侧的「坐标」按钮打开（天气失败卡片里也有入口）。对话框支持：

- 纬度 / 经度分栏输入，带范围校验（-90~90 / -180~180）
- 坐标系选择：**WGS-84**（GPS/户外轨迹/本应用）、**GCJ-02**（高德/腾讯）、**BD-09**（百度），
  内部自动换算成 WGS-84，避免峰顶偏移几百米
- 可选地点名称，留空则显示为「自定义坐标」
- 确定后自动飞到该点并查询天气

省额度策略：

- 本地库**精确/前缀命中**时，下拉建议不再请求高德（`LOCAL_STRONG_SCORE = 80`）；
- 所有高德/Mapbox 结果按查询词做 5 分钟内存缓存，重复查询零请求；
- 下拉建议有 250ms 防抖，只有本地库没有强命中时才发高德请求。

## 数据流

1. 输入地名 → 先查本地山峰库（`App.matchPeaks`）→ 未命中再走高德 → 再兜底 Mapbox
2. 高德返回 GCJ-02 → `coord-transform.js` 转 WGS-84；Mapbox 直接是 WGS-84
3. Mapbox 标记/飞行，Mapbox DEM 采样峰顶海拔
4. Open-Meteo 请求该点多模型天气，输出云海/日出预测与安全建议

## 维护本地山峰库

编辑 `js/peaks-db.js` 的 `App.PEAKS_DB`，一条记录：

```js
{n:'船底顶', aliases:['船底顶穿越','罗坑船底顶'], lat:24.4810, lon:113.2620,
 elev:1586, region:'广东 · 韶关/曲江', cat:'gd'}
```

- `lat`/`lon` 必须是 **WGS-84**（不是高德/百度的 GCJ-02、BD-09）
- `cat`：`hot` 热门徒步、`scenic` 景区徒步、`gd` 广东热门、`world` 境外山峰
- `home`：可选，首页「经典」快捷按钮的排序位（1 最靠前，需唯一）；不加则只在搜索里出现
- `elev` 可省略，省略时运行时用 Mapbox DEM / 天气网格高程补
- 改完运行校验，会检查名称/别名重复、坐标范围、分类、海拔与 `home` 序号合法性：

```powershell
npm run check:peaks
```

### 首页快捷按钮（自动生成）

首页的「经典 / 广东热门」两排按钮**不再单独维护坐标**，而是从 `peaks-db` 实时生成：

- 「广东热门」＝ `cat:'gd'` 的全部条目（当前 24 个），按 peaks-db 顺序排列；
- 「经典」＝ 带 `home: 序号` 的条目（当前 12 个），按序号排序；
- 新增一座山只要在 peaks-db 补一条记录：想进「广东热门」用 `cat:'gd'`，
  想进「经典」再加 `home` 序号，两边都不需要改别的文件。

## 轨迹上传：一个代表点代表整个区域

天气预报本身就是**区域网格数据**（Open-Meteo 网格约 1~11 km），一条徒步轨迹通常落在同一个
网格里。逐点取天气不会更准，只会多打请求、给出"虚假的精度"。因此：

1. 上传 GPX / KML 后解析轨迹、统计总距离 / 累计爬升 / 海拔范围；
2. 从轨迹里选**一个区域代表点**：有海拔数据时取最高点（山顶/垭口，最影响登山安全与
   日出云海判断），没有海拔则取轨迹几何中心；
3. 用这个代表点查询主天气面板，这份预报即代表整条轨迹所在区域；
4. 地图上保留轨迹线与关键点标记（仅展示，不再逐点查天气）。

这样一条轨迹只消耗一次天气查询（主预报 + 多模型对比），而不是 N 次。

## 已知限制

- 完整 PWA 安装（Service Worker 离线缓存）需通过 http(s) 部署后启用，`file://` 不支持。
- 极个别小众山峰高德未收录、本地库也没有时，只能靠 Mapbox 兜底（精度有限），
  建议直接输入经纬度。
- 高德个人 key 有日配额/QPS 限制，长期大量查询请申请企业配额。

## 常见问题：天气数据加载不出来

天气数据来自 Open-Meteo（`api.open-meteo.com`），页面用 `fetch` 直接请求，**不依赖任何第三方
CDN 脚本**。因此：

1. 如果页面能打开但右侧一直停在"正在获取…"或显示「天气数据获取失败」，先看提示文案：
   - 「网络连接失败：无法访问天气服务」→ 本机网络/代理访问不到 Open-Meteo，可换网络或用代理后点「重试」。
   - 「天气服务异常 (5xx)」→ 上游接口临时故障，稍后重试即可。
2. 地图空白、图表区提示「图表库（ECharts）未加载」→ jsDelivr 被拦截/超时。此时
   `js/deps.js` 会自动改用备用源（unpkg、BootCDN、staticfile）补载，天气查询本身不受影响。
3. 如果天气和地图同时失效，检查浏览器控制台（F12）里的报错；`file://` 下个别浏览器会限制
   网络请求，建议用本地静态服务打开：

```powershell
npx http-server -p 8080
```
